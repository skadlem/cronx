## Independent findings (outside any A-id)

1. **Uppercase-macro divergence, now ruled** — `crontab -n` REJECTS every non-lowercase macro spelling (@YEARLY, @WEEKLY, @MIDNIGHT, @ReBoot → "bad time specifier"): vixie's macro table is case-SENSITIVE, while charter R-003 mandates case-insensitive acceptance and ADR-004 pins `@REBOOT`. A-015's criterion text names only ADR-012/ADR-007 as divergence licences; the coordinator ruled on 2026-09-05 that this is a third documented, charter-mandated divergence class (cronx ACCEPT / crontab REJECT) — implemented and asserted in `test_uppercase_macros_diverge_charter_mandated`, NOT treated as a product bug. An ADR sentence recording it would make the paper trail fully self-describing.
2. **Two malformed-element forms accepted by the host cron, outside the pinned corpus**: `1-2-3 * * * *` and `*/2/3 * * * *` → cron ACCEPTS (vixie's get_list parses the prefix and stops), cronx REJECTS as malformed. No ADR covers them and they are not KB/ADR/"Pinned by" expressions, so they are deliberately excluded from the differential corpus (A-015's note pins the corpus; reviewer may not invent cases). cronx's reject is the charter-aligned behaviour (R-010 "reject rather than guess"); flagged so the planner can decide whether an ADR line is warranted. Measured via the same harness (probe rc verified both directions).
3. **5-fields-plus-command lines**: `0 0 1 * * 0` / `0 0 1 * * 2026` are accepted by cron because the 6th token is read as the COMMAND — exactly the confusion ADR-007's 2026-09-05 amendment addresses with its crontab-LINE hint; excluded from the agree corpus for that reason (it is a line-vs-expression dialect difference, not a grammar verdict).
4. **`zoneinfo._zoneinfo` private-API coupling in test_tz_errors** — implementer-flagged and reviewed OK: the pure-Python ZoneInfo with `clear_cache()` and live-TZPATH reads exists unchanged in 3.9–3.14, so the missing-tzdb pin is 3.9-legal; a future C-cache-clear API could simplify it.
5. **`crontab -n` exits 0 with a warning** on `1-5/10 * * * *` ("Step size 10 higher than possible maximum of 4") — verdict accept, cronx accept; no action.
6. No product bug found: nothing required a reproduce-as-failing-test; zero failures, zero skips, and no assertion was weakened anywhere (only files created by this wave: tests/test_differential.py and this report — cronx/ sources and all existing tests untouched).
